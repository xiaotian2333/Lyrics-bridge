# WinIsland Bridge 插件接口文档

本文档描述 `winisland-bridge` 插件当前使用的 WebSocket 对接协议，供 WinIsland 或其他外部软件实现服务端后与 EchoMusic 插件通信。

## 1. 连接方式

插件作为 WebSocket 客户端，外部软件需要作为 WebSocket 服务端。

默认连接地址：

```text
ws://127.0.0.1:17195
```

用户可以在 EchoMusic 的插件设置中修改服务端地址。

连接建立后，插件会主动发送：

1. 当前曲目歌词同步事件 `track_lyrics`，仅当 EchoMusic 当前已加载到真实歌词时发送
2. 订阅事件 `subscribe`
3. 每 10 秒发送一次 `ping`

## 2. 通用消息格式

所有消息均为 JSON 字符串。

```json
{
  "type": "消息类型",
  "seq": 1,
  "payload": {}
}
```

字段说明：

| 字段 | 类型 | 方向 | 说明 |
| --- | --- | --- | --- |
| `type` | `string` | 双向 | 消息类型 |
| `seq` | `number` | 插件发出时存在 | 插件侧自增序号，用于调试或应答关联 |
| `payload` | `object` / `array` | 双向 | 消息载荷，不同 `type` 结构不同 |

说明：

- 插件不会强制要求服务端返回 `ack`
- 插件收到 `pong` 或 `ack` 会直接忽略
- 插件收到无法解析的 JSON 会忽略

## 3. 插件发送给服务端的消息

### 3.1 subscribe

连接建立后发送，用于声明插件希望接收的事件类别。

```json
{
  "type": "subscribe",
  "seq": 1,
  "payload": {
    "events": ["control", "state", "media"]
  }
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `payload.events` | `string[]` | 插件声明订阅的事件类别，目前固定为 `control`、`state`、`media` |

### 3.2 ping

插件连接成功后每 10 秒发送一次心跳。

```json
{
  "type": "ping"
}
```

服务端可以选择返回：

```json
{
  "type": "pong"
}
```

插件收到 `pong` 后不会执行额外逻辑。

### 3.3 track_lyrics

插件向服务端推送“当前曲目 + 真实歌词”。旧事件名 `lyrics` 已不再准确，当前版本改为 `track_lyrics`。

```json
{
  "type": "track_lyrics",
  "seq": 2,
  "payload": {
    "track": {
      "id": "123456",
      "title": "歌曲名",
      "artist": "歌手 A、歌手 B",
      "artists": ["歌手 A", "歌手 B"]
    },
    "lyrics": [
      {
        "time_ms": 3430,
        "text": "第一句歌词"
      },
      {
        "time_ms": 15620,
        "text": "第二句歌词"
      }
    ]
  }
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `payload.track` | `object` | 当前歌词所属歌曲信息，用于避免切歌或异步加载时产生歧义 |
| `payload.track.id` | `string` | 歌曲标识，优先来自 EchoMusic 当前曲目的 `id`，兜底使用 `songId` 或 `hash` |
| `payload.track.title` | `string` | 歌名，优先来自 `title`，兜底使用 `name` |
| `payload.track.artist` | `string` | 歌手文本，多个歌手用 `、` 拼接 |
| `payload.track.artists` | `string[]` | 歌手数组 |
| `payload.lyrics` | `array` | 歌词行数组 |
| `payload.lyrics[].time_ms` | `number` | 歌词时间戳，单位毫秒 |
| `payload.lyrics[].text` | `string` | 歌词文本 |

重要行为：

- 当前版本要求 **必须有真实歌词才发送 `track_lyrics` 事件**
- 歌词加载中不会发送 `track_lyrics`
- 当前歌曲没有歌词时不会发送 `track_lyrics`
- 切歌后插件会在多个时间点重试读取歌词，读取到真实歌词后才发送 `track_lyrics`
- 不会发送空歌词事件，例如不会主动发送：

```json
{
  "type": "track_lyrics",
  "payload": {
    "track": {
      "title": "歌曲名",
      "artist": "歌手"
    },
    "lyrics": []
  }
}
```

触发时机：

| 时机 | 行为 |
| --- | --- |
| WebSocket 连接成功 | 如果当前已有真实歌词，则发送一次 `track_lyrics` |
| 收到 `request_track_lyrics` 命令 | 如果当前已有真实歌词，则发送一次 `track_lyrics` |
| 收到兼容命令 `request_lyrics` | 如果当前已有真实歌词，也会发送一次 `track_lyrics` |
| EchoMusic 曲目切换 | 等待歌词加载，读取到真实歌词后发送一次 `track_lyrics` |

切歌后的重试时间点：

```text
300ms, 800ms, 1500ms, 3000ms, 5000ms
```

当某次重试成功发送真实歌词后，后续未执行的重试会被取消。

## 4. 服务端发送给插件的消息

### 4.1 command

服务端可以发送 `command` 消息控制 EchoMusic。

```json
{
  "type": "command",
  "payload": {
    "action": "play",
    "data": {}
  }
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `payload.action` | `string` | 控制动作 |
| `payload.data` | `object` | 动作参数，可选 |

支持的 `action`：

| action | data | 说明 |
| --- | --- | --- |
| `request_track_lyrics` | 无 | 请求插件立即推送当前曲目真实歌词；没有真实歌词时不会发送 |
| `request_lyrics` | 无 | 兼容旧命令；行为等同于 `request_track_lyrics`，响应事件仍为 `track_lyrics` |
| `show_notification` | `{ "title": string, "message": string }` | 在 EchoMusic 内显示提示消息 |
| `play` | 无 | 播放 |
| `pause` | 无 | 暂停 |
| `toggle_play` | 无 | 切换播放 / 暂停 |
| `next` | 无 | 下一首 |
| `prev` | 无 | 上一首 |
| `seek` | `{ "position_ms": number }` | 跳转到指定播放位置，单位毫秒；兼容 `time_ms`、`position`、`time`、`currentTime` 字段，其中不带 `_ms` 的字段按秒处理 |

#### request_track_lyrics 示例

请求插件推送当前曲目真实歌词：

```json
{
  "type": "command",
  "payload": {
    "action": "request_track_lyrics"
  }
}
```

插件响应示例：

```json
{
  "type": "track_lyrics",
  "seq": 3,
  "payload": {
    "track": {
      "id": "123456",
      "title": "歌曲名",
      "artist": "歌手",
      "artists": ["歌手"]
    },
    "lyrics": [
      {
        "time_ms": 1000,
        "text": "歌词内容"
      }
    ]
  }
}
```

如果 EchoMusic 当前歌词仍在加载，或当前歌曲没有歌词，插件不会发送 `track_lyrics`。

#### seek 示例

```json
{
  "type": "command",
  "payload": {
    "action": "seek",
    "data": {
      "position_ms": 65000
    }
  }
}
```

插件会调用 EchoMusic 播放器跳转到 `65` 秒。

#### show_notification 示例

```json
{
  "type": "command",
  "payload": {
    "action": "show_notification",
    "data": {
      "title": "WinIsland",
      "message": "已连接"
    }
  }
}
```

插件会在 EchoMusic 内显示：

```text
WinIsland: 已连接
```

### 4.2 pong

服务端可以响应插件的 `ping`。

```json
{
  "type": "pong"
}
```

插件收到后会忽略，不需要额外字段。

### 4.3 ack

服务端可以发送确认消息。

```json
{
  "type": "ack",
  "seq": 1
}
```

插件收到后会忽略，不需要额外字段。

### 4.4 state

插件当前只保留了 `state` 消息入口，暂未实现实际同步逻辑。

```json
{
  "type": "state",
  "payload": {
    "media": {}
  }
}
```

当前行为：

- 当 `type` 为 `state` 且 `payload.media` 存在时，插件不会报错
- 目前不会根据 `payload.media` 修改 EchoMusic 状态

## 5. 推荐服务端实现流程

1. 在本机启动 WebSocket 服务端，监听 `127.0.0.1:17195`
2. 等待 EchoMusic 插件连接
3. 收到 `subscribe` 后记录连接已就绪
4. 收到 `ping` 后可选返回 `pong`
5. 收到 `track_lyrics` 后按 `payload.track` 确认歌曲，再处理 `payload.lyrics`
6. 如需控制播放，向插件发送 `command`

## 6. Node.js 服务端示例

```js
import { WebSocketServer } from 'ws'

const wss = new WebSocketServer({ host: '127.0.0.1', port: 17195 })

wss.on('connection', (socket) => {
  console.log('EchoMusic 插件已连接')

  socket.on('message', (raw) => {
    const msg = JSON.parse(raw.toString())
    console.log('收到消息:', msg)

    if (msg.type === 'ping') {
      socket.send(JSON.stringify({ type: 'pong' }))
      return
    }

    if (msg.type === 'track_lyrics') {
      console.log('收到歌曲:', msg.payload.track.title, '-', msg.payload.track.artist)
      console.log('收到真实歌词:', msg.payload.lyrics)
    }
  })

  // 请求当前曲目歌词
  socket.send(JSON.stringify({
    type: 'command',
    payload: {
      action: 'request_track_lyrics',
    },
  }))
})
```

## 7. 兼容性说明

- 旧事件名 `lyrics` 已被 `track_lyrics` 取代
- 旧命令 `request_lyrics` 暂时保留兼容，但响应事件名仍是 `track_lyrics`
- 新接入软件应使用 `request_track_lyrics` 请求歌词

## 8. 注意事项

- 插件是 WebSocket 客户端，外部软件必须先启动 WebSocket 服务端
- 默认地址是 `ws://127.0.0.1:17195`
- `track_lyrics` 事件只代表“当前曲目的真实歌词”，不再用于清空歌词
- 如果外部软件需要在切歌时清空旧歌词，应结合自身的播放状态来源处理，或等待下一次真实歌词覆盖
- 插件自动重连默认开启，断开后约 5 秒尝试重连

# Lyrics-bridge 插件接口文档

本文档描述 `Lyrics-bridge` 插件当前使用的 WebSocket 对接协议，供 EchoMusic-Lyrics-WinIsland 或其他外部软件实现服务端后与 EchoMusic 插件通信。
本文档仅描述插件与服务端之间的通信协议，不涉及插件内部逻辑。插件和服务端均可能不完全支持全部规范，但不支持的规范需要忽略，不得导致异常运行。

## 1. 连接方式

插件作为 WebSocket 客户端，外部软件需要作为 WebSocket 服务端。

默认连接地址：

```text
ws://127.0.0.1:17195
```

用户可以在 EchoMusic 的插件设置中修改服务端地址。

连接建立后，插件会主动发送：

1. 当前音量设置命令 `source: "plugin" + action: "set_volume"`，用于让服务端先同步 EchoMusic 当前音量
2. 当前音乐数据同步事件 `MusicData`，仅当 EchoMusic 当前已加载到真实歌词时发送
3. 订阅事件 `subscribe`
4. 每 10 秒发送一次 `ping`

服务端在连接建立后会主动发送：

1. 全量配置快照 `config_snapshot`（见第 8 节）

## 2. 通用消息格式

所有消息均为 JSON 字符串。

```json
{
  "type": "消息类型",
  "seq": 1,
  "payload": {}
}
```

字段说明：

| 字段 | 类型 | 方向 | 说明 |
| --- | --- | --- | --- |
| `type` | `string` | 双向 | 消息类型 |
| `seq` | `number` | 插件发出时存在 | 插件侧自增序号，用于调试或应答关联 |
| `payload` | `object` / `array` | 双向 | 消息载荷，不同 `type` 结构不同 |

说明：

- 插件不会强制要求服务端返回 `ack`
- 插件收到 `pong` 或 `ack` 会直接忽略
- 插件收到无法解析的 JSON 会忽略

## 3. 插件发送给服务端的消息

### 3.1 subscribe

连接建立后发送，用于声明插件希望接收的事件类别。

```json
{
  "type": "subscribe",
  "seq": 1,
  "payload": {
    "events": ["control", "state", "media"]
  }
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `payload.events` | `string[]` | 插件声明订阅的事件类别，目前固定为 `control`、`state`、`media` |

### 3.2 ping

插件连接成功后每 10 秒发送一次心跳。

```json
{
  "type": "ping"
}
```

服务端可以选择返回：

```json
{
  "type": "pong"
}
```

插件收到 `pong` 后不会执行额外逻辑。

### 3.3 MusicData

插件向服务端推送"当前曲目元数据 + 音乐封面 + 歌词（如有）"。无论当前是否有真实歌词，插件都会发送此事件。

```json
{
  "type": "MusicData",
  "seq": 2,
  "payload": {
    "Metadata": {
      "id": "123456",
      "title": "歌曲名",
      "artist": "歌手 A、歌手 B",
      "artists": ["歌手 A", "歌手 B"],
      "cover_base64": "/9j/4AAQSkZJRgABAQAAAQABAAD...",
      "is_favorite": true,
      "play_mode": "list"
    },
    "lyrics": [
      {
        "time_ms": 3430,
        "text": "第一句歌词",
        "characters": [
          { "s": 3430, "e": 3550, "t": "第" },
          { "s": 3550, "e": 3670, "t": "一" },
          { "s": 3670, "e": 3790, "t": "句" },
          { "s": 3790, "e": 3910, "t": "歌" },
          { "s": 3910, "e": 4030, "t": "词" }
        ],
        "translated": "First line of lyrics",
        "romanized": "dai yi ju ge ci"
      },
      {
        "time_ms": 15620,
        "text": "第二句歌词",
        "characters": [
          { "s": 15620, "e": 15800, "t": "第" },
          { "s": 15800, "e": 16000, "t": "句" }
        ],
        "translated": "Second line of lyrics"
      }
    ]
  }
}
```

无歌词时的示例：

```json
{
  "type": "MusicData",
  "seq": 2,
  "payload": {
    "Metadata": {
      "id": "123456",
      "title": "歌曲名",
      "artist": "歌手 A、歌手 B",
      "artists": ["歌手 A", "歌手 B"],
      "cover_base64": "/9j/4AAQSkZJRgABAQAAAQABAAD...",
      "is_favorite": true,
      "play_mode": "random"
    },
    "lyrics": []
  }
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `payload.Metadata` | `object` | 当前歌词所属歌曲元数据，用于避免切歌或异步加载时产生歧义 |
| `payload.Metadata.id` | `string` | 歌曲标识，优先来自 EchoMusic 当前曲目的 `id`，依次兜底 `songId`、`playback.trackId`、`hash`、`playback.lyricHash`。`playback.trackId` 为快照中的曲目 ID，`playback.lyricHash` 为快照中的歌词哈希 |
| `payload.Metadata.title` | `string` | 歌名，优先来自 `playback.title`，依次兜底 `track.title`、`track.name` |
| `payload.Metadata.artist` | `string` | 歌手文本，多个歌手用 `、` 拼接。由 `track.artists` 生成，若 `artists` 不存在则依次兜底 `track.singers`、`playback.artist`、`track.artist`。`track.singers` 为曲目数据中兼容旧版本的歌手数组字段 |
| `payload.Metadata.artists` | `string[]` | 歌手数组 |
| `payload.Metadata.cover_base64` | `string` | 音乐封面图片的 Base64 编码字符串；只包含 Base64 内容，不带 `data:image/...;base64,` 前缀；无封面或读取失败时为空字符串 |
| `payload.Metadata.is_favorite` | `boolean` | 当前歌曲是否为 EchoMusic 用户收藏歌曲；无法确认时为 `false` |
| `payload.Metadata.play_mode` | `string` | 当前播放模式，取值 `"sequential"`（顺序播放）、`"list"`（列表循环）、`"random"`（随机播放）、`"single"`（单曲循环）。仅在支持播放模式切换的播放器中有效，无法获取时默认为 `"list"` |
| `payload.lyrics` | `array` | 歌词行数组，当前没有真实歌词时为空数组 |
| `payload.lyrics[].time_ms` | `number` | 歌词时间戳，单位毫秒 |
| `payload.lyrics[].text` | `string` | 歌词文本 |
| `payload.lyrics[].characters` | `array` | 逐字数组，存在逐字数据时提供（见下方注意事项） |
| `payload.lyrics[].characters[].s` | `number` | 该字开始时间，单位毫秒 |
| `payload.lyrics[].characters[].e` | `number` | 该字结束时间，单位毫秒 |
| `payload.lyrics[].characters[].t` | `string` | 该字文本 |
| `payload.lyrics[].translated` | `string` | 翻译文本，无翻译时不存在此字段 |
| `payload.lyrics[].translated_characters` | `array` | 翻译逐字数组，结构与 `characters` 同，存在逐字数据时提供 |
| `payload.lyrics[].romanized` | `string` | 音译文本（罗马音等），无音译时不存在此字段 |
| `payload.lyrics[].romanized_characters` | `array` | 音译逐字数组，结构与 `characters` 同，存在逐字数据时提供 |

#### 关于逐字歌词的注意事项

> 逐字数据由 EchoMusic 从歌词源（如 KRC/YRC 格式）解析获得，**并非所有歌词都包含字符级时间戳**。  
> 若歌词行无 `characters` 字段或该字段不存在，表示该行无逐字数据，外部软件应回退到整行高亮。  
> `translated_characters` 和 `romanized_characters` 同理，仅在对应数据存在时提供。

重要行为：

- 无论是否有真实歌词，插件都会发送 `MusicData` 事件
- `payload.lyrics` 在无歌词时为空数组 `[]`
- 封面不存在或读取失败不会阻止发送，`payload.Metadata.cover_base64` 会为空字符串
- 歌词由异步加载时，插件先发送歌词为空数组的 `MusicData`，待歌词加载完成后再次发送完整 `MusicData`
- 歌词来源变化（如歌词重新加载、翻译/罗马音切换导致歌词数据变更）时也会发送一次完整 `MusicData`

触发时机：

| 时机 | 行为 |
| --- | --- |
| WebSocket 连接成功 | 发送一次 `MusicData` |
| EchoMusic 曲目切换 | 发送一次 `MusicData`（可能无歌词） |
| 歌词数据变更 | 同一歌曲的歌词数据发生变更（如异步加载完成、翻译/罗马音切换）时，发送一次完整 `MusicData` |

> 插件不自动重试推送歌词。若服务端收到的 `MusicData` 中 `lyrics` 为空数组，应自行通过 `request_MusicData` 指数退避轮询。

服务端重试机制：

服务端收到 `lyrics` 为空数组的 `MusicData` 后，应自行实现指数退避重试来获取歌词，而非依赖插件侧的定时推送：

```text
推荐退避策略：1s → 2s → 4s → 8s → 上限 30s
```

服务端在每个退避间隔向插件发送 `request_MusicData` 命令，插件在歌词就绪后会再次推送完整 `MusicData`。服务端收到带歌词的 `MusicData` 后应停止重试。

## 4. 控制命令（双向）

`command` 消息现在支持双向发送：服务端可以向插件发送命令控制 EchoMusic，插件也可以向服务端发送命令同步外部软件状态。

### 4.1 命令格式

```json
{
  "type": "command",
  "source": "server",
  "payload": {
    "action": "play",
    "data": {}
  }
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `source` | `string` | 命令发起方标识，`"plugin"` 或 `"server"` |
| `payload.action` | `string` | 控制动作 |
| `payload.data` | `object` | 动作参数，可选 |

### 4.2 服务端发送给插件的命令（source: "server"）

服务端可以通过以下 `action` 控制 EchoMusic：

| action | data | 说明 |
| --- | --- | --- |
| `request_MusicData` | 无 | 请求插件立即推送当前曲目的 `MusicData`；插件会尝试读取歌词并发送（可能仍为空数组），用于服务端指数退避重试 |
| `get_playback_state` | 无 | 请求插件立即回复当前播放状态；插件以 `source: "plugin" + action: "position"` 回复 |
| `get_software_info` | 无 | 请求插件回复软件信息；插件以 `source: "plugin" + action: "software_info"` 回复 |
| `upload_music_file` | `{ "upload_url": string }` | 请求插件将当前播放音频文件上传到指定地址；插件使用 HTTP POST + `Content-Type: audio/*` 发送二进制音频数据到 `{upload_url}/Music-file-upload`，并在请求头中附加歌曲元数据 |
| `show_notification` | `{ "title": string, "message": string }` | 在 EchoMusic 内显示提示消息 |
| `show_main_window` | 无 | 请求插件处理窗口唤起；仅当 EchoMusic 主窗口处于托盘隐藏状态时由插件拉起 EchoMusic，其余状态下插件会向服务端发送 `source: "plugin" + action: "show_main_window"` |
| `play` | 无 | 播放 |
| `pause` | 无 | 暂停 |
| `toggle_play` | 无 | 切换播放 / 暂停 |
| `next` | 无 | 下一首 |
| `prev` | 无 | 上一首 |
| `seek` | `{ "position_ms": number }` | 跳转到指定播放位置，单位毫秒；兼容 `time_ms`、`position`、`time`、`currentTime` 字段，其中不带 `_ms` 的字段按秒处理。以上字段也可直接位于 `payload` 层级（`msg.payload.position_ms` 等），用于兼容旧版消息结构 |
| `start_seek_sync` | `{ "interval": number }` | 启动高速进度同步；插件连接 `/seek` WebSocket 并按指定固定间隔（单位毫秒，允许范围 `10` 到 `1000`）推送播放进度；详见第 9 节 |
| `update_seek_sync` | `{ "interval": number }` | 动态调整高速进度同步的推送间隔（单位毫秒，允许范围 `10` 到 `1000`）；插件收到后立即切换；详见第 9 节 |
| `stop_seek_sync` | 无 | 停止高速进度同步；插件关闭 `/seek` WebSocket 连接，停止所有进度推送；详见第 9 节 |
| `set_volume` | `{ "volume": number }` | 设置 EchoMusic 音量；`volume` 使用 `0` 到 `1` 的小数，有效精度为小数点后最多 3 位，`0` 表示静音音量，`1` 表示最大音量 |
| `set_favorite` | `{ "is_favorite": boolean, "id"?: string }` | 收藏或取消收藏当前歌曲；`id` 存在时用于校验目标歌曲，不存在时默认作用于当前歌曲。校验时除 `id` 外，还依次匹配 `songId`、`hash`、`mixSongId`、`fileId`、`playback.trackId`、`playback.lyricHash` 等曲目身份候选字段，任一匹配即视为同一首歌曲。`mixSongId` 和 `fileId` 为曲目数据中兼容旧版本的标识字段 |
| `set_play_mode` | `{ "mode": string }` | 设置 EchoMusic 的播放模式；`mode` 取值 `"sequential"`（顺序播放）、`"list"`（列表循环）、`"random"`（随机播放）、`"single"`（单曲循环）；非法值或无法设置时静默忽略 |

#### seek 示例（服务端→插件）

```json
{
  "type": "command",
  "source": "server",
  "payload": {
    "action": "seek",
    "data": {
      "position_ms": 65000
    }
  }
}
```

插件会调用 EchoMusic 播放器跳转到 `65` 秒。

#### start_seek_sync 示例（服务端→插件）

```json
{
  "type": "command",
  "source": "server",
  "payload": {
    "action": "start_seek_sync",
    "data": {
      "interval": 100
    }
  }
}
```

插件收到后连接 `/seek` WebSocket，以 100ms 的固定间隔推送播放进度。

#### update_seek_sync 示例（服务端→插件）

```json
{
  "type": "command",
  "source": "server",
  "payload": {
    "action": "update_seek_sync",
    "data": {
      "interval": 500
    }
  }
}
```

插件收到后立即将推送间隔调整为 500ms。

#### stop_seek_sync 示例（服务端→插件）

```json
{
  "type": "command",
  "source": "server",
  "payload": {
    "action": "stop_seek_sync",
    "data": {}
  }
}
```

插件收到后关闭 `/seek` WebSocket 连接，停止所有进度推送。

#### set_volume 示例（服务端→插件）

服务端请求 EchoMusic 将音量设置为 80%：

```json
{
  "type": "command",
  "source": "server",
  "payload": {
    "action": "set_volume",
    "data": {
      "volume": 0.8
    }
  }
}
```

插件收到后应将 EchoMusic 音量设置为该值。`volume` 无法解析为有限数字时忽略；小于 `0` 或大于 `1` 时按 `0` 或 `1` 裁剪后应用；超过 3 位小数时，接收方按四舍五入保留 3 位小数后应用。

#### set_favorite 示例（服务端→插件）

服务端请求 EchoMusic 收藏当前歌曲：

```json
{
  "type": "command",
  "source": "server",
  "payload": {
    "action": "set_favorite",
    "data": {
      "id": "123456",
      "is_favorite": true
    }
  }
}
```

服务端请求 EchoMusic 取消收藏当前歌曲时，将 `is_favorite` 设为 `false`。若提供 `id`，插件应确认该 `id` 与当前歌曲一致后再执行；若不提供 `id`，默认作用于当前歌曲。

#### show_notification 示例

```json
{
  "type": "command",
  "source": "server",
  "payload": {
    "action": "show_notification",
    "data": {
      "title": "WinIsland",
      "message": "已连接"
    }
  }
}
```

插件会在 EchoMusic 内显示：

```text
WinIsland: 已连接
```

#### show_main_window 示例与行为

服务端发送：

```json
{
  "type": "command",
  "source": "server",
  "payload": {
    "action": "show_main_window",
    "data": {}
  }
}
```

插件收到后执行：

- 先判断 EchoMusic 主窗口是否处于托盘隐藏状态
- 如果主窗口处于托盘隐藏状态，插件将 EchoMusic 主窗口拉起到前台
- 如果主窗口不是托盘隐藏状态，包括已处于前台、后台未聚焦、最小化等状态，插件不处理 EchoMusic 窗口，而是向服务端发送 `source: "plugin" + action: "show_main_window"`
- 如果 EchoMusic 已完全退出，插件也已停止运行，服务端无法通过该协议唤起应用
- 该指令不要求服务端等待 `ack`；如服务端需要确认，可以按通用消息格式自行发送 `ack`，插件收到后会忽略

插件转发给服务端：

```json
{
  "type": "command",
  "source": "plugin",
  "payload": {
    "action": "show_main_window",
    "data": {}
  }
}
```

服务端收到 `source: "plugin" + action: "show_main_window"` 后，应拉起外部软件主窗口。服务端不应将该指令原样回发给插件，避免形成循环。

#### upload_music_file 示例与行为

服务端发送：

```json
{
  "type": "command",
  "source": "server",
  "payload": {
    "action": "upload_music_file",
    "data": {
      "upload_url": "http://192.168.1.100:8080"
    }
  }
}
```

插件收到后执行：

- 以 HTTP `POST` 请求发送到 `{upload_url}/Music-file-upload`
- `Content-Type: audio/*`
- 请求体为当前播放音频的二进制数据（从播放引擎或内存中直接获取，不产生额外网络请求）
- 附加自定义请求头携带歌曲元数据：

| Header | 值 | 说明 |
| --- | --- | --- |
| `X-Music-Id` | 当前曲目 `id` | 歌曲标识 |
| `X-Music-Title` | 当前曲目标题 | URL 编码后发送 |
| `X-Music-Artist` | 当前曲目歌手 | `、` 拼接，URL 编码后发送 |

插件不关注响应体内容，仅当 HTTP 状态码为 `200` 时视为上传成功，其余情况静默忽略。

### 4.3 插件发送给服务端的命令（source: "plugin"）

当 EchoMusic 的播放状态、收藏状态或窗口唤起处理结果发生变化，或插件需要请求外部软件调整音量时，插件会主动向服务端发送以下命令：

| action | data | 触发时机 |
| --- | --- | --- |
| `play` | `{ "position_ms": number }` | 用户或系统切换到播放状态 |
| `pause` | `{ "position_ms": number }` | 用户或系统切换到暂停状态 |
| `toggle_play` | `{ "position_ms": number }` | 播放/暂停切换（仅在无法明确得知当前状态时发送） |
| `next` | 无 | 用户或系统切到下一首 |
| `prev` | 无 | 用户或系统切到上一首 |
| `seek` | `{ "position_ms": number, "cause"?: string }` | 用户拖动进度条、系统媒体控制等非自然播放进度变化 |
| `position` | `{ "position_ms": number, "duration_ms": number, "is_playing": boolean }` | 响应服务端 `get_playback_state` 命令，回复当前播放进度与状态 |
| `software_info` | `{ "name": string, "version": string, "author": string }` | 响应服务端 `get_software_info` 命令，回复软件信息 |
| `show_main_window` | 无 | 插件未处理 EchoMusic 唤起请求时，请求服务端拉起外部软件主窗口 |
| `set_volume` | `{ "volume": number }` | 连接建立时同步 EchoMusic 当前音量，或本地音量变化时请求服务端将外部软件音量设置为指定值；`volume` 有效精度为小数点后最多 3 位 |
| `set_favorite` | `{ "is_favorite": boolean, "id"?: string }` | 用户在 EchoMusic 内收藏或取消收藏歌曲 |
| `set_play_mode` | `{ "mode": string }` | EchoMusic 内播放模式被用户切换时通知服务端同步；`mode` 取值 `"sequential"`（顺序播放）、`"list"`（列表循环）、`"random"`（随机播放）、`"single"`（单曲循环） |
| `get_config` | 无 | 请求服务端立即推送当前全量配置；服务端以 `config_snapshot` 消息回复 |
| `open_font_picker` | 无 | 请求服务端打开系统字体选择对话框；选择后服务端更新 `custom_font_path` 并以 `config_snapshot` 推送 |
| `open_folder_picker` | `{ "purpose": string }` | 请求服务端打开文件夹选择对话框；`purpose` 为用途标识（当前固定为 `"covers"`），选择后服务端更新对应路径并以 `config_snapshot` 推送 |
| `check_updates_now` | 无 | 请求服务端立即检查更新 |
| `open_homepage` | 无 | 请求服务端在默认浏览器中打开项目主页 |

字段说明：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `data.name` | `string` | 否（仅 software_info） | 软件名称，仅在 `action: "software_info"` 时存在 |
| `data.version` | `string` | 否（仅 software_info） | 软件版本号，仅在 `action: "software_info"` 时存在 |
| `data.author` | `string` | 否（仅 software_info） | 软件作者，仅在 `action: "software_info"` 时存在 |
| `data.position_ms` | `number` | 是（仅 play/pause/toggle_play/seek/position） | 当前播放进度，单位毫秒。插件从播放快照的 `playback.currentTime` 读取，若不存在则兜底 `playback.position`。`currentTime` 为快照中兼容旧版本的进度字段名 |
| `data.duration_ms` | `number` | 否（仅 position） | 当前曲目总时长，单位毫秒，仅在 `action: "position"` 时存在 |
| `data.is_playing` | `boolean` | 否（仅 position） | 当前是否处于播放状态，仅在 `action: "position"` 时存在 |
| `data.volume` | `number` | 是（仅 set_volume） | 目标音量，范围 `0` 到 `1`，有效精度为小数点后最多 3 位，`0` 表示静音音量，`1` 表示最大音量。接收方收到 `set_volume` 后自行设置本端音量；无法解析为有限数字时忽略，超出范围时裁剪到 `[0, 1]` 后应用；超过 3 位小数时按四舍五入保留 3 位小数后应用 |
| `data.is_favorite` | `boolean` | 是（仅 set_favorite） | 当前歌曲是否为 EchoMusic 用户收藏歌曲，仅在 `action: "set_favorite"` 时存在 |
| `data.id` | `string` | 否（仅 set_favorite） | 歌曲标识，用于服务端确认收藏状态所属歌曲 |
| `data.cause` | `string` | 否 | seek 的触发原因，取值 `"user"`、`"system"`、`"external"`，仅在 `action: "seek"` 时存在。服务端收到无 `cause` 的 seek 时应始终执行跳转 |

#### 自然推进不通知

播放进度的自然秒级推进不会触发 `seek` 通知。仅当插件检测到进度发生 **非自然跳转**（用户拖拽进度条、系统媒体控制跳转、外部 IPC 调用了 seek 等）时，才发送 `source: "plugin"` + `action: "seek"`。

#### seek 防闭环机制

1. 服务端发送 `source: "server" + action: "seek"` → 插件执行跳转
2. 插件**不**对此条命令产生的进度变化再次发送 `seek` 通知
3. 仅当 seek 的发起方 **不是** 服务端（用户拖进度条、系统媒体控制、EchoMusic 内部其他操作等）时，插件才发送 `source: "plugin" + action: "seek"` 通知给服务端
4. 服务端收到 `source: "plugin"` 的 `seek` 通知后，根据 `data.cause` 决定是否响应

#### seek 示例（插件→服务端）

```json
{
  "type": "command",
  "source": "plugin",
  "payload": {
    "action": "seek",
    "data": {
      "position_ms": 65000,
      "cause": "user"
    }
  }
}
```

响应服务端 `get_playback_state`：

#### set_volume 示例（插件→服务端）

插件请求外部软件将音量设置为 80%：

```json
{
  "type": "command",
  "source": "plugin",
  "payload": {
    "action": "set_volume",
    "data": {
      "volume": 0.8
    }
  }
}
```

服务端收到后应将外部软件音量设置为该值。该消息表示设置请求，不是状态通知；服务端应用该设置后，不应将同值 `set_volume` 原样立即回发给插件，避免形成循环。

#### set_favorite 示例（插件→服务端）

EchoMusic 内用户取消收藏当前歌曲后，插件通知服务端同步外部软件状态：

```json
{
  "type": "command",
  "source": "plugin",
  "payload": {
    "action": "set_favorite",
    "data": {
      "id": "123456",
      "is_favorite": false
    }
  }
}
```

服务端收到 `source: "plugin" + action: "set_favorite"` 后，应按 `data.id` 确认歌曲，再使用 `data.is_favorite` 更新外部软件中的收藏按钮或状态。

### 4.4 pong

服务端可以响应插件的 `ping`。

```json
{
  "type": "pong"
}
```

插件收到后会忽略，不需要额外字段。

### 4.5 ack

服务端可以发送确认消息。

```json
{
  "type": "ack",
  "seq": 1
}
```

插件收到后会忽略，不需要额外字段。

### 4.6 state

插件当前只保留了 `state` 消息入口，暂未实现实际同步逻辑。

```json
{
  "type": "state",
  "payload": {
    "media": {}
  }
}
```

当前行为：

- 当 `type` 为 `state` 且 `payload.media` 存在时，插件不会报错
- 目前不会根据 `payload.media` 修改 EchoMusic 状态

### 3.7 disabled

插件被用户禁用、卸载或 EchoMusic 退出时，插件会向服务端发送插件已禁用通知。

```json
{
  "type": "command",
  "source": "plugin",
  "payload": {
    "action": "disabled",
    "data": {}
  }
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `type` | `string` | 固定为 `"command"` |
| `source` | `string` | 固定为 `"plugin"` |
| `payload.action` | `string` | 固定为 `"disabled"` |
| `payload.data` | `object` | 当前为空对象，保留未来扩展 |

触发时机：

| 时机 | 说明 |
| --- | --- |
| 用户在 EchoMusic 插件管理页中禁用插件 | 插件 deactivate 前发送 |
| 用户卸载插件 | 插件 deactivate 前发送 |
| EchoMusic 应用退出 | 插件 deactivate 前发送 |

> 该消息在 WebSocket 连接关闭前发送。服务端收到此消息后可以清理该插件的资源、断开关联的 UI 或停止与该插件相关的数据推送。

## 5. 推荐服务端实现流程

1. 在本机启动 WebSocket 服务端，监听 `127.0.0.1:17195`
2. 等待 EchoMusic 插件连接
3. 收到 `subscribe` 后记录连接已就绪
4. 收到 `ping` 后可选返回 `pong`
5. 收到 `MusicData` 后按 `payload.Metadata` 确认歌曲，再处理 `payload.Metadata.cover_base64`、`payload.Metadata.is_favorite` 和 `payload.lyrics`
6. 收到 `source: "plugin"` 的 `command` 后同步外部软件状态；若 action 为 `set_volume`，按 `data.volume` 设置外部软件音量；若 action 为 `set_favorite`，按 `data.id` 和 `data.is_favorite` 更新收藏状态；若 action 为 `show_main_window`，拉起外部软件主窗口且不要原样回发给插件
7. 连接建立后尽快发送 `config_snapshot`，使插件设置面板显示当前配置
8. 收到 `config_update` 后更新对应配置项并持久化
9. 收到 `get_config` 命令后发送 `config_snapshot`
10. 收到 `open_font_picker` / `open_folder_picker` 命令后打开原生选择器，更新配置后推送 `config_snapshot`
11. 收到 `check_updates_now` / `open_homepage` 命令后执行对应操作
12. 如需控制播放、修改音量或修改收藏状态，向插件发送 `source: "server" + command`
13. 如需请求插件处理窗口唤起，向插件发送 `source: "server" + action: "show_main_window"`；插件仅在 EchoMusic 处于托盘隐藏状态时拉起 EchoMusic，其余状态会回发 `source: "plugin" + action: "show_main_window"`
14. 收到 `source: "plugin" + action: "disabled"` 后清理该插件相关的资源，停止与该插件相关的数据推送
15. 如需高速进度同步，在 `/seek` 路径上建立独立的 WebSocket 服务；通过 `start_seek_sync` 启动、`update_seek_sync` 动态调频、`stop_seek_sync` 停止推送
16. 收到 `source: "plugin" + action: "disabled"` 时确保关闭 `/seek` 连接，清理对应资源

## 6. Node.js 服务端示例

```js
import { WebSocketServer } from 'ws'

const wss = new WebSocketServer({ host: '127.0.0.1', port: 17195 })

wss.on('connection', (socket) => {
  console.log('EchoMusic 插件已连接')

  socket.on('message', (raw) => {
    const msg = JSON.parse(raw.toString())
    console.log('收到消息:', msg)

    if (msg.type === 'ping') {
      socket.send(JSON.stringify({ type: 'pong' }))
      return
    }

    if (msg.type === 'MusicData') {
      const metadata = msg.payload.Metadata
      console.log('收到歌曲:', metadata.title, '-', metadata.artist)
      console.log('收到封面 Base64:', metadata.cover_base64 ? `${metadata.cover_base64.length} 字符` : '无')
      console.log('收到真实歌词:', msg.payload.lyrics)
    }
  })
})
```

## 7. 注意事项

- 插件是 WebSocket 客户端，外部软件必须先启动 WebSocket 服务端
- 默认地址是 `ws://127.0.0.1:17195`
- `MusicData` 的 `payload.Metadata.cover_base64` 是 Base64 文本，服务端需要自行解码后再作为图片使用
- `MusicData` 的 `payload.Metadata.is_favorite` 表示 EchoMusic 内当前歌曲收藏状态，服务端应优先使用该字段初始化外部软件的收藏按钮状态
- 如果外部软件需要在切歌时清空旧歌词，应结合自身的播放状态来源处理，或等待下一次真实歌词覆盖
- 插件自动重连默认开启，断开后约 5 秒尝试重连
- 音量控制使用 `source: "server"` / `source: "plugin"` 双向 `set_volume` 命令，`data.volume` 范围为 `0` 到 `1`，有效精度为小数点后最多 3 位；接收方应用后不要将同值原样立即回发，避免形成循环
- 封面 URL 处理时，插件会自动将旧 CDN 域名 `c1.kgimg.com` 替换为 `imge.kugou.com`，用于兼容旧版本封面地址格式。若 URL 中包含 `{size}` 占位符，会被替换为 `400`

## 8. 配置同步协议

配置同步协议允许插件通过 WebSocket 读取和修改服务端（EchoMusic-Lyrics-WinIsland）的运行时配置，使 EchoMusic 内的插件设置面板能够完全复刻服务端原生设置窗口的所有设置项。

### 8.1 消息概览

| 消息类型 | 方向 | 说明 |
| --- | --- | --- |
| `config_snapshot` | 服务端 → 插件 | 全量配置快照，包含所有 AppConfig 字段 |
| `config_update` | 插件 → 服务端 | 增量配置更新，修改单个配置项 |

### 8.2 config_snapshot

服务端向插件推送全量运行时配置。

```json
{
  "type": "config_snapshot",
  "payload": {
    // 服务端全量运行时配置，字段由服务端定义
  }
}
```

#### 触发时机

| 时机 | 行为 |
| --- | --- |
| WebSocket 连接建立后 | 服务端立即发送一次 `config_snapshot` |
| 插件发送 `get_config` 命令 | 服务端回复 `config_snapshot` |
| 服务端配置发生变更 | 服务端自动广播 `config_snapshot` |
| 服务端原生设置窗口保存修改 | 服务端自动广播 `config_snapshot` |

### 8.3 config_update

插件向服务端发送增量配置更新。每次只修改一个配置项，服务端收到后立即应用并持久化。

```json
{
  "type": "config_update",
  "seq": 10,
  "payload": {
    "path": "show_lyrics",
    "value": false
  }
}
```

#### 字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `payload.path` | `string` | 配置项路径，与 `config_snapshot.payload` 中的字段名一致 |
| `payload.value` | 任意 | 配置项的新值，类型需与文档定义一致 |

#### 支持的 path 取值

`path` 对应 `config_snapshot.payload` 中的字段名，插件可修改除 `custom_font_path` 之外的所有配置项。  
`custom_font_path` 的修改通过 `open_font_picker` / `open_folder_picker` 命令触发服务端原生对话框完成，插件不直接发送该字段的 `config_update`。

#### 服务端行为

1. 收到 `config_update` 后验证 `value` 类型和范围合法性
2. 应用配置变更到运行时状态
3. 持久化到配置文件
4. 回复 `ack` 消息
5. 当 `config_update` 涉及其他连接插件的共享配置时，服务端应广播 `config_snapshot` 给所有连接的插件

## 9. 高速播放进度同步协议

高速播放进度同步协议允许服务端以毫秒级精度实时获取 EchoMusic 的播放进度，适用于需要精确同步进度显示的场景（如外部歌词窗口进度条）。

### 9.1 概述

- 使用**独立的 WebSocket 连接**，入口为 `ws://127.0.0.1:17195/seek`
- **默认不启用**，需服务端通过主 WebSocket 下发命令触发
- 该连接**仅用于高频进度同步**，所有其他通讯仍走主 WebSocket
- 插件→服务端**单向推送**，服务端无需回复
- 推送间隔由服务端指定，支持动态调整

### 9.2 生命周期

```
服务端（主WS）下发 start_seek_sync
    │
    ▼
插件连接 ws://.../seek
    │
    ▼
插件按指定固定间隔推送进度
    │
    ├── 服务端下发 stop_seek_sync → 关闭连接，停止推送
    ├── 连接意外断开 → 静默停止，不复连
    └── 服务端下发 update_seek_sync → 调整推送间隔，继续推送
```

### 9.3 服务端命令

通过主 WebSocket 的 `command` 消息控制启停和频率：

| action | data | 说明 |
| --- | --- | --- |
| `start_seek_sync` | `{ "interval": number }` | 启动同步。`interval` 为固定推送间隔（单位毫秒），允许范围为 `10` 到 `1000`，示例值：`100` 极高频、`300` 高频、`1000` 中频 |
| `update_seek_sync` | `{ "interval": number }` | 动态调整推送间隔。`interval` 允许范围为 `10` 到 `1000`，插件收到后立即切换 |
| `stop_seek_sync` | 无 | 停止同步。插件关闭 `/seek` 连接 |

### 9.4 推送数据格式（插件 → 服务端）

插件通过 `/seek` WebSocket 发送扁平 JSON，每条消息一个进度点：

```json
{
  "position_ms": 65000,
  "is_playing": true
}
```

**字段说明：**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `position_ms` | `number` | 当前播放进度，单位毫秒。参考现有 `action.seek` 的 `position_ms` 字段，但不提供 `cause` 字段 |
| `is_playing` | `boolean` | 当前是否处于播放状态 |

### 9.5 连接管理

| 操作 | 行为 |
| --- | --- |
| 建立连接 | 插件收到 `start_seek_sync` 后连接 `ws://127.0.0.1:17195/seek`，连接成功后立即开始推送 |
| 关闭连接 | 插件收到 `stop_seek_sync`、插件被禁用或 EchoMusic 退出时关闭 |
| 意外断开 | **不主动重连**，静默停止推送。需服务端再次下发 `start_seek_sync` 重新建立连接 |
| 非法间隔 | `interval` 缺失、非法或超出 `10` 到 `1000` 范围时，插件停止高速进度同步 |

### 9.6 与现有 seek 协议的关系

- `/seek` WS 的进度推送**仅用于同步显示**，不影响插件内部的防闭环机制（`lastServerSeekTriggered` 标志）
- 服务端如需跳转播放进度，仍通过主 WS 发送 `source: "server" + action: "seek"` 命令
- 插件检测到的非自然 seek 跳转（用户拖拽进度条等）仍由主 WS 的 `source: "plugin" + action: "seek"` 通知

### 9.7 参考文档

详细规范（推送规则、切歌/暂停行为、连接建立等）见 `docs/高频进度同步协议.md`，本文档仅记述主接口层面的交互流程。

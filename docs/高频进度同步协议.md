# Lyrics-bridge 高速播放进度同步协议

本文档描述 `Lyrics-bridge` 插件的高速播放进度同步协议。该协议为独立于主 WebSocket 连接的补充协议，用于实现毫秒级精度的播放进度高频推送。

## 设计目标

- **独立连接**：高频进度同步走单独的 WebSocket 连接，不干扰主连接的其他通讯
- **按需启用**：默认不启用，由服务端下发命令触发
- **频率可控**：推送间隔由服务端决定，支持动态调整
- **单向推送**：仅插件向服务端推送，服务端无需回复
- **轻量传输**：消息格式精简，减少高频传输的开销

## 连接入口

```
ws://127.0.0.1:17195/seek
```

端口与主 WebSocket 一致，路径固定为 `/seek`。

## 默认状态

该接口**默认不启用**。插件启动后不会主动连接 `/seek`，也不会进行任何高频进度推送。仅当服务端通过主 WebSocket 下发启动命令后，插件才建立 `/seek` 连接并开始推送。

---

## 1. 生命周期

```
服务端（主WS）下发 start_seek_sync
    │
    ▼
插件连接 ws://127.0.0.1:17195/seek
    │
    ▼
插件按指定间隔向 /seek WS 推送进度
    │
    ▼
服务端（主WS）下发 stop_seek_sync
    │
    ▼
插件关闭 /seek WS 连接，停止推送


连接意外断开
    │
    ▼
静默停止，不复连
```

服务端可在同步运行期间通过主 WS 下发 `update_seek_sync` 动态调整推送频率。若 `/seek` 连接意外断开，插件不会主动重连，需等待服务端再次下发 `start_seek_sync`。

## 2. 服务端 → 插件命令（通过主 WebSocket）

以下命令通过已有的主 WebSocket 连接（`ws://127.0.0.1:17195`）发送，使用现有 `command` 消息格式（`type: "command"`、`source: "server"`）。

### 2.1 start_seek_sync — 启动高频进度同步

服务端通知插件启动高速进度同步。插件收到后应：

1. 建立 `/seek` WebSocket 连接
2. 按 `interval` 指定的固定间隔开始推送

```json
{
  "type": "command",
  "source": "server",
  "payload": {
    "action": "start_seek_sync",
    "data": {
      "interval": 100
    }
  }
}
```

**字段说明：**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `data.interval` | `number` | 是 | 固定推送间隔，单位毫秒，允许范围为 `10` 到 `1000`。插件每次推送后固定等待该时长发起下一次推送。若该值缺失、非法或超出范围，插件停止高速进度同步 |

### 2.2 update_seek_sync — 动态调整推送频率

服务端在同步运行期间动态修改推送间隔。

```json
{
  "type": "command",
  "source": "server",
  "payload": {
    "action": "update_seek_sync",
    "data": {
      "interval": 500
    }
  }
}
```

**字段说明：**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `data.interval` | `number` | 是 | 新的固定推送间隔，单位毫秒，允许范围为 `10` 到 `1000`。插件收到后应立即切换为该间隔；若该值缺失、非法或超出范围，插件停止高速进度同步 |

### 2.3 stop_seek_sync — 停止高频进度同步

服务端通知插件停止高速进度同步。插件收到后应：

1. 关闭 `/seek` WebSocket 连接
2. 停止所有进度推送
3. 清理内部计时器等资源

```json
{
  "type": "command",
  "source": "server",
  "payload": {
    "action": "stop_seek_sync",
    "data": {}
  }
}
```

## 3. 插件 → 服务端推送（通过 /seek WebSocket）

插件通过 `/seek` WebSocket 连接向服务端单向推送播放进度数据。服务端**无需回复**任何消息。

### 3.1 消息格式

```json
{
  "position_ms": 65000,
  "is_playing": true
}
```

**字段说明：**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `position_ms` | `number` | 是 | 当前播放进度，单位毫秒。参考现有 `action.seek` 的 `position_ms` 字段，但不提供 `cause` 字段 |
| `is_playing` | `boolean` | 是 | 当前是否处于播放状态 |

### 3.2 推送规则

| 规则 | 说明 |
| --- | --- |
| 开始推送 | 插件收到 `start_seek_sync` 后，建立 `/seek` 连接，连接成功后立即开始推送 |
| 推送间隔 | 每次推送后固定等待 `interval` 毫秒，然后发起下一次推送 |
| 停止推送 | 插件收到 `stop_seek_sync` 后关闭连接、停止推送 |
| 连接断开 | `/seek` 连接意外断开后，插件**不会**主动重连，静默停止推送。需等待服务端再次下发 `start_seek_sync` 时重新建立连接 |
| 切歌行为 | 切歌不影响 `/seek` 连接和推送节奏；`position_ms` 正常反映新的播放进度即可 |
| 暂停行为 | 暂停时 `is_playing` 为 `false`，`position_ms` 保持暂停时的位置；恢复播放后恢复正常推送 |

### 3.3 与主 WS seek 命令的关系

- `/seek` WS 的进度推送**仅用于同步显示**，服务端按需消费
- 服务端如需跳转播放进度，仍通过主 WS 发送 `source: "server" + action: "seek"` 命令
- `/seek` WS 的推送**不会**触发插件内部的防闭环逻辑（`lastServerSeekTriggered` 标志不受影响）
- 插件检测到的非自然 seek 跳转（用户拖拽进度条等）仍由主 WS 的 `source: "plugin" + action: "seek"` 通知，与 `/seek` 推送无关

## 4. 连接管理

### 4.1 连接建立

- 服务端需要监听 `ws://127.0.0.1:17195/seek` 路径
- 插件在收到 `start_seek_sync` 后主动连接该路径
- 如果服务端不支持 `/seek` 路径，插件应静默忽略连接失败，不影响主 WebSocket 连接

### 4.2 连接关闭

以下情况插件应主动关闭 `/seek` 连接：

| 时机 | 说明 |
| --- | --- |
| 收到 `stop_seek_sync` 命令 | 正常停止 |
| 插件被禁用 | 插件 deactivate 时关闭 |
| EchoMusic 应用退出 | 插件 deactivate 时关闭 |

### 4.3 意外断开

`/seek` 连接意外断开后，插件**不会**主动重连，静默停止所有推送。后续如需恢复高频进度同步，由服务端重新下发 `start_seek_sync` 触发。

---

## 5. 主 WebSocket 与 /seek WebSocket 职责对比

| 维度 | 主 WebSocket（`ws://...:17195`） | `/seek` WebSocket（`ws://...:17195/seek`） |
| --- | --- | --- |
| 用途 | 通用通讯：歌词推送、播放控制、配置同步、状态通知等 | **仅**用于高频播放进度同步 |
| 消息方向 | 双向（插件 ↔ 服务端） | 单向（仅插件 → 服务端） |
| 消息格式 | 通用 JSON 格式（含 `type`、`seq`、`payload` 等） | 扁平 JSON（仅 `position_ms` + `is_playing`） |
| 开启条件 | 插件启动即自动连接 | 服务端通过主 WS 下发 `start_seek_sync` 后才连接 |
| 推送频率 | 事件驱动，非固定间隔 | 固定间隔由服务端通过 `interval` 指定，支持动态调整 |
| 服务端回复 | 支持 `pong`、`ack` 等应答 | 无需回复任何消息 |
